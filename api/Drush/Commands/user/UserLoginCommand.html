UserLoginCommand

class UserLoginCommand (View source)

internal  
 

Runs dr user:login, the one-time login link that ships with Drupal core 11.4+.

As with cache:rebuild, the Bootstrap attribute keeps Drush from bootstrapping Drupal fully before handing over to dr, which bootstraps on its own. It stops at the SITE level rather than NONE so that Drush can tell dr which site directory the uri selects (see DoctorTrait::siteEnvironment()). Messages are plain strings for the same reason: t() needs Drupal's container.

protected array siteEnvironment(BootstrapManager $bootstrapManager)

Environment variables that make dr select the same site as Drush.

dr reads DRUPAL_URI for the commands it boots Drupal for. Its cache:rebuild builds the request from $_SERVER instead, which in CLI holds the environment, so the host is passed as HTTP_HOST as well.

For the commands it boots Drupal for, dr builds its request without a script name, which keeps DrupalKernel::findSitePath() from selecting a multisite directory from the uri alone. When Drush has bootstrapped to the SITE level it knows the directory, and passes it along as DRUPAL_DEV_SITE_PATH, the override core reads before findSitePath().
