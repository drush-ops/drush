UpdatedbCommand

final class UpdatedbCommand (View source)

internal  
 

Runs under dr only. Drush keeps its own updatedb.

dr boots the standard kernel, so this command switches to the container update.php runs with (UpdateServiceProvider: null caches, a compiler pass that tolerates missing services) by rebuilding the container itself, and switches back at the end. Updates run in-process as a non-progressive batch.

Sends Drupal log messages to the console.

dr does this once per command through ConsoleSubscriber, but a container rebuild replaces logger.console with an instance that has no console logger attached, so it is done again after every rebuild. It also lets kernel tests see the log output.

protected void afterOperation(ContainerInterface $before, OutputInterface $output)

Keeps a rebuilt update container out of the site's container cache.

The kernel caches every container it compiles. While the update provider is registered that container must not be served to web requests, so the cache entry is deleted whenever the container instance changed, which also happens when an update installs a module. Console logging is re-attached for the same reason.
